# Agents guide — expense_tracker

This file is a concise, actionable guide for AI coding agents working on this Flutter project.

1) Big-picture architecture
- Flutter single-app with feature-first layout: see `lib/features/*` (Home, Expense, Track, Friend, Profile).
- Shared UI and theme pieces are under `lib/core/*` (e.g. `core/Common/CommonAppBar.dart`, `core/Common/CustomBottomNav.dart`, `core/constants/colors.dart`).
- Local persistence uses Hive: model at `lib/data/model/expense_model.dart` and storage wrapper at `lib/data/local/expense_storage.dart`.
- Entry point: `lib/main.dart` — Hive is initialized and the `expenses` box is opened here.

2) Data flows and service boundaries
- UI -> ViewModel (ChangeNotifier) -> ExpenseStorage -> Hive box. Example: `lib/Demo/viewmodel/expense_viewmodel.dart` calls `ExpenseStorage.addExpense`, which writes to Hive via `_box.put(expense.id, expense)`.
- Keys: IDs are strings (example generation: `DateTime.now().microsecondsSinceEpoch.toString()` in demo viewmodel). Box name: `"expenses"`.
- Generated code: models use Hive TypeAdapters (see `part 'expense_model.g.dart'`). Whenever models change run codegen (see below).

3) Project-specific conventions and patterns
- Feature folder structure: each feature contains widgets, optional `bottomsheet/` UI, `model/`, and `viewmodel/` (e.g. `lib/features/Expense/` and `lib/features/Track/FoodTracking/`).
- UI pattern: many screens are built as StatefulWidgets with local setState updates wrapped around viewmodel calls (see `lib/Demo/home_screen.dart`). The project currently uses ChangeNotifier-based viewmodels directly without a global Provider tree.
- Bottom sheets are the common create/edit UX surface (look under `*/bottomsheet/*`, e.g. `create_expense_card_sheet.dart`). They typically collect input and then call viewmodel/storage.
- Styling: centralized color and formatter helpers: `lib/core/constants/colors.dart` and `lib/core/utils/formatters.dart`.

4) Integration points & external deps
- Dependencies in `pubspec.yaml`: hive, hive_flutter, hive_generator (dev), build_runner (dev), intl, provider (declared but not wired up in `main.dart`).
- Native build/config: `android/` and `ios/` folders are standard Flutter projects. Android builds use Gradle wrappers in `android/`.

5) Developer workflows (commands you must run)
- Get dependencies: `flutter pub get`
- Regenerate Hive adapters after changing annotated models: `flutter pub run build_runner build --delete-conflicting-outputs` (important — `expense_model.g.dart` is generated). If adding/removing Hive fields, migrate carefully (typeId must be stable).
- Run app: `flutter run -d <deviceId>` or use IDE run configurations. Example for Windows: `flutter run -d windows`.
- Run analyzer/tests: `flutter analyze` and `flutter test`.
- Build release APK: `flutter build apk`; Android bundle: `flutter build appbundle`.

6) Safety notes / gotchas for agents
- Hive TypeId stability: `@HiveType(typeId: 0)` in `expense_model.dart` — do NOT reuse/change existing typeIds without migration steps; changing fields reorders adapter behavior.
- Box access: code assumes `Hive.openBox<Expense>('expenses')` has already run in `main.dart`. When writing new modules, ensure box is opened before usage (usually in `main`).
- State wiring: `provider` is listed in `pubspec.yaml` but not used in `main.dart`. If adding global providers, modify `main.dart` to wrap `runApp` with `MultiProvider`.

7) Where to look for examples
- Persisting items: `lib/data/local/expense_storage.dart` and `lib/Demo/viewmodel/expense_viewmodel.dart`.
- Navigation / app shell: `lib/MainScreen.dart` (bottom nav + drawer + feature screens list).
- UI building pattern / bottomsheet UX: `lib/features/Expense/bottomsheet/create_expense_card_sheet.dart` and many `*/bottomsheet/*` files.

8) Typical agent tasks and shortcuts
- Small feature (UI + local persist): create a bottomsheet under the feature, call corresponding viewmodel method and update storage; follow ID generation used in `Demo/viewmodel/expense_viewmodel.dart`.
- Add a new Hive model: add `@HiveType` annotated class, then run build_runner to generate adapter and register it in `main.dart` with `Hive.registerAdapter(YourAdapter());`.
- Wire a global provider: edit `lib/main.dart` to wrap `ExpenseTrackerApp` with `MultiProvider`, add `ChangeNotifierProvider(create: (_) => ExpenseViewModel(ExpenseStorage()))`.

If something is ambiguous, first inspect these files: `lib/main.dart`, `lib/data/model/expense_model.dart`, `lib/data/local/expense_storage.dart`, `lib/Demo/viewmodel/expense_viewmodel.dart`, `lib/MainScreen.dart`.
